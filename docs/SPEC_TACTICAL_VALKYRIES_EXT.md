## 8. 序盤サバイバルと技術進行フェーズ (Early Game & Progression)

未来技術（時空テレポート、ルミナル変換、重粒子砲）を持たない最序盤において、バニラ資源と泥臭い物理兵站で兵姫を再起動・修復し、二人三脚で立ち上がるための仕様。

### 8.1 進行ステージ遷移 (Progression Stages)

* **Stage 0 [漂着と蘇生]**:
  * 墜落ポッド自然生成 ➔ 手動ダイナモ・石炭スタンドで微小給電 ➔ 記憶破損状態の兵姫が目覚める。
* **Stage 1 [ジャンク兵站と野良斥候戦]**:
  * バニラホッパー・チェストによる物理弾薬補給 ➔ スクラップ銃・振動刃で武装 ➔ 野良ドローン撃破。
* **Stage 2 [クロノ工学のブレイクスルー]**:
  * 敵ドロップ「歪んだクロノ破片」を携帯アナライザーで解析 ➔ 兵姫の記憶領域復旧 ➔ Tier 1 局所テレポートマシン解禁。
* **Stage 3 [前哨基地強襲・上位工学]**:
  * 敵前哨基地へ攻城レイド ➔ ルミナルエナジーアダプター稼働 ➔ 上位合金＆AEC級ボス戦へ。

### 8.2 墜落ポッド (Crashed Drop Pod)

* **ワールド生成**: 地表または浅い地下（Y=40〜80）に稀に生成される3×3×3の黒焦げ構造体。
* **構成ブロック**: `crashed_pod_hull` (硬度高、ツルハシで破壊可)、`damaged_interface`。
* **内包物**:
  * スリープ状態の `EntityValkyrie` (素体ランダム、HP 5/40、コア電力 0)。
  * ポッド内のチェストに `item_portable_analyzer`、破損した弾薬、少量の鉄・銅インゴット。
* **実装（2026-10-07 ユーザー指定）**（`world/CrashedPods`・`block/DamagedInterfaceBlock`）:
  * 生成: ワールドの初期スポーンから 60〜200 m に 1 つ確定（最初の 1 回だけ置く）。ほかはオーバーワールドの陸地（海・川・浜以外）に平均 800 m 四方に 1 つ（`placed_feature/crashed_pod` の rarity 2500）
  * 形: 黒焦げの外殻（`crashed_pod_hull`、5×4×5、1 段埋まる、角を丸め天井が少し破れる）、前面に入口、まわりに焦げ跡（粗い土・ブラックストーン、草花は消える）。中に眠る兵姫・奥の壁の `damaged_interface`・チェスト（`loot_tables/chests/crashed_pod`: 鉄・銅インゴット、歪んだクロノ破片、徹甲弾（破損した弾薬の代わり）、レッドストーン、50% で空のプロトコア）
  * `damaged_interface` は**目覚めの端末**: 満充電のプロトコアを持って右クリックすると、6 ブロック以内の深い休眠の兵姫が目覚め、使った人が持ち主になる（プロトコアの 100,000 FE が兵姫に入り、プロトコアは使い切る）。眠っている兵姫は右クリックで持ち主にできず、電力が入っても端末以外では起きない
  * 兵姫は HP 5・電力 0。素体は Type-V だけ（S / H / C のモデルができたらランダムに）。`item_portable_analyzer` はまだアイテムが無いので入れていない

## 9. 資源圧縮階層システム (Resource Compression Hierarchy)

素材を `3×3` クラフト（またはアダプター相転移）で圧縮し、上位エネミーや上位ダンジョンほど高圧縮された素材を直接ドロップするハクスラ・ファクトリー連携仕様。

### 9.1 圧縮レート定義

* **Tier 0 [単位素材 (Unit)]**: 1個
* **Tier 1 [ブロック (Block)]**: 単位素材 × 9 (作業台 `3×3` またはアダプター)
* **Tier 2 [オーブ (Orb)]**: ブロック × 9 (単位素材 81個分)
* **Tier 3 [スター (Star)]**: オーブ × 9 (単位素材 729個分)
* **Tier 4 [コア (Core)]**: スター × 9 (単位素材 6,561個分)

### 9.2 3大基幹リソースの圧縮ツリー

| 階層 (Tier) | ① クロノ系 (時空・重装甲) | ② ルミナル系 (光子・高出力) | ③ ナノ系 (生体・修復) |
| :--- | :--- | :--- | :--- |
| **Tier 0 [素材]** | `drop_chrono_scrap`<br>(クロノスクラップ) | `crystal_luminal`<br>(ルミナルクリスタル) | `drop_nanomachine`<br>(リアナノマシン) |
| **Tier 1 [ブロック]**| `block_chrono_metal`<br>(耐爆・時空固定) | `block_luminal_gem`<br>(常時発光・高誘電) | `block_nano_mesh`<br>(自己修復多孔質) |
| **Tier 2 [オーブ]** | `orb_chronos`<br>(空間跳躍のオーブ) | `orb_luminal`<br>(光子励起のオーブ) | `orb_nano`<br>(再生変異のオーブ) |
| **Tier 3 [スター]** | `star_chronos`<br>(因果断絶のクロノスター) | `star_luminal`<br>(恒星崩壊のルミナルスター) | `star_nano`<br>(原初の死生ナノスター) |
| **Tier 4 [コア]** | `core_singularity_chronos`<br>(時空特異点クロノコア) | `core_genesis_luminal`<br>(創世ルミナルコア) | `core_catastrophe_nano`<br>(終焉再生ナノコア) |

### 9.3 敵・基地ドロップ＆直接利用機能

* **野良ドローン / 斥候**: Tier 0 (スクラップ / クリスタル) を 1〜3個 ドロップ。
* **Tier 1 基地 (前哨基地)**: Tier 1 (ブロック) をチェスト・タレット残骸から入手。
* **Tier 2 基地 / AEC級ボス**: Tier 2 (オーブ) を直接ドロップ。
* **Tier 3 基地 / タイムルーラー**: Tier 3 (スター) を直接ドロップ。
* **裏ボス (ロストカタストロフィー)**: Tier 4 (各コア) を確定ドロップ。
* **実用消費効果**:
  * `orb_luminal`: 右クリックまたは給電ドック投入で **5,000,000 FE** を瞬時充填。
  * `star_nano`: 兵姫スリープ（HP0）時に使用で、フルHP・フルシールドで即時戦線復帰。
  * `core_genesis_luminal`: マシンにセットすると、**毎秒 1,000,000 FE を永久無償発電**。

### 9.4 実装状況（2026-10-02、暫定）

* **実装済み（素材として）**: Tier 0 の `drop_chrono_scrap`・`drop_nanomachine`・`crystal_luminal`、Tier 1 の `block_chrono_metal`・`block_nano_mesh`・`block_luminal_gem`、Tier 2 の `orb_chronos`・`orb_nano`・`orb_luminal`、Tier 3 の `star_chronos`・`star_luminal`・`star_nano`。各段は 3×3 で圧縮、1 個から 9 個に展開できる
  * `block_chrono_metal`（耐爆・時空固定）: 爆発耐性 1200、ピストンで動かない。採掘は鉄のツルハシ以上
  * `block_nano_mesh`（自己修復多孔質）: 弱く光り（明るさ 4）、ナノマシンの緑の粒をにじませる。自己修復の挙動はまだ無い
  * オーブ・スターは核が明滅するアニメーションと系統ごとの粒子（クロノ = 紫の時空、ナノ = 緑、ルミナル = 金と白）。スターは付与のきらめき付き
* **敵ドロップ**: `drop_chrono_scrap`・`drop_nanomachine` と、§8.1 Stage 2 の「歪んだクロノ破片」（`drop_distorted_chrono_shard`、ID は仮決め）。**敵を実装するまではクリエイティブで取り出すだけ**（敵ができたら §9.3 のとおりドロップにつなぐ）
* **未実装**: Tier 4 のコア（裏ボス素材を兼ねるので後で）、上の実用消費効果（`orb_luminal` の FE 充填・`star_nano` の兵姫の復帰は兵姫・給電ドックを作ってから）

## 10. 侵食基地ダンジョンと防衛兵器 (Corrupted Base Dungeons & Siege Units)

プレイヤー拠点を守るタワーディフェンスではなく、敵の防衛網へ兵姫と共に乗り込む「攻城レイド型」システム。

### 10.1 基地ストラクチャ階層

* **Tier 1: クロノ・アウトリポスト (前哨監視基地)**
  * 地表施設。小規模な通信塔と外周タレットで構成。目的: 通信中枢の破壊と初期ブロック鹵獲。
* **Tier 2: ディメンション・ファウンドリ (時空兵站工場)**
  * 地下〜地表の複合ダンジョン。プレス機トラップ、組立ライン、無敵力場発生器が存在。
* **Tier 3: クロノ・バスティオン (浮遊移動要塞)**
  * 上空 Y=180 以上に滞空する超巨大要塞。AEC級ボスおよびタイムルーラーへのポータルを内包。

### 10.2 基地固有の防衛設備 (Defense Entities & Blocks)

1. **パルス・ファランクス (`entity_pulse_phalanx`)**:
   * 固定対空タレット。射程40m。プレイヤーのエリトラ飛行や長距離射撃を感知し、迎撃弾幕を掃射。
2. **ヘビー・シージキャノン (`entity_siege_cannon`)**:
   * 大口径榴弾固定砲。遮蔽物越しに山なり曲射（着弾地点に大爆発＋ノックバック）。
3. **位相アンカー・ジェネレーター (`block_phase_anchor`)**:
   * 基地深部を覆う紫色の無敵バリア供給源。周囲のサブ・コンデンサー（3〜4箇所）を全破壊するまで無敵。
4. **警報ドローン『サイレン・アイ』 (`entity_siren_eye`)**:
   * 侵入者発見時にアラーム鳴動。防衛ハッチから増援ドローンを毎10秒スポーンさせる。暗殺最優先対象。
5. **クロノ・ガーディアン (`entity_chrono_guardian`)**:
   * 基地内通路を巡回する大型多脚機。大型シールドで通路を塞ぎ、高圧スタンロッドで近接迎撃。

### 10.3 兵姫の攻城AIルーチン (`ValkyrieSiegeGoal`)

* **ポイントマン前進**: プレイヤーが遠距離武器所持時、シールド持ち兵姫が自動で前方半歩に立ち射線を遮蔽。
* **タレット・警報優先撃破**: 雑魚よりもタレット・サイレン・アイをAIが最優先ターゲットとしてロック。
* **防衛円陣 (Defensive Perimeter)**: プレイヤーがジェネレーター破壊・ハッキング中、背中合わせで360度迎撃。

## 11. 外部工業MOD連携アーキテクチャ (Cross-Mod Integration)

MOD単体で完全自己完結しつつ、外部工業MODの導入時に生産力・兵站が爆発的に向上するアダプティブ設計。

### 11.1 連携マトリクス仕様

（見出しの本文は未受領。以下は受領した連携マトリクス）

| 連携先工業MOD | 提供されるブースト・連携機能 |
|---|---|
| Mekanism | ・鉱石の3〜5倍化ライン完全対応 (スラリー/浸出/濃縮)<br>・核融合/超大容量FEによるルミナル相転移の即時完了<br>・液体窒素/冷却材を給電ドックへ注入 ➔ 熱蓄積完全無効化 |
| Applied Energistics 2 / Refined Storage | ・給電ドックにMEインターフェース直結<br>・兵姫の回収ドロップを直接MEストレージへ自動搬入<br>・弾薬/ナノリペア剤の自動クラフト発注・無限補給 |
| Create | ・回転動力(Stress)をオルタネーター経由で初期給電変換<br>・ベルトコンベア/メカニカルアームによる物理弾薬供給 |
| Thermal Expansion / Ender IO | ・アロイスメルターによる上位合金配合 (FE消費30%カット)<br>・ゲル化クリオセウムによる兵装強制冷却 |

### 11.1.1 連携用の共通金属（2026-10-02 実装、暫定）

単体でも工業 MOD と同じ金属が手に入るよう、主要な共通金属を同じ `forge:` タグで持つ（どの MOD のインゴットとも相互に代わりに使える）。登録は `registry/IndustrialMetals`。

* **基本金属（鉱石あり）**: スズ・鉛・銀・ニッケル・亜鉛・アルミニウム・オスミウム・ウラン。粗鉱・粗鉱ブロック・鉱石（石・深層岩）＋共通の形。鉱石の生成はオーバーワールド・台形分布で、`automata_valkyries-worldgen.toml` の `[ores]` で金属ごとに切れる。**同じ金属の鉱石を他 MOD がそのバイオームに生成していれば、こちらは自動で生成しない**（`skipWhenOtherModGenerates`、既定 true。§11.1.5）
* **合金（鉱石なし）**: 鋼鉄・青銅・真鍮・エレクトラム・インバー・コンスタンタン
* **共通の形**: インゴット・塊・ブロック・粉・板・歯車・棒（`forge:ingots/nuggets/storage_blocks/dusts/plates/gears/rods`）。バニラの鉄・銅・金の粉も持つ
* **暫定のクラフト**（マシンができたら置き換える）: 粉 = インゴット + 火打石、板 = インゴット 2 個を横に、棒 = 縦に 2 個で 4 本、歯車 = インゴット 4 個で塊を囲む、粉の精錬・溶鉱でインゴット。合金の粉の調合: 青銅 = 銅 3 + スズ 1 → 4、真鍮 = 銅 3 + 亜鉛 1 → 4、エレクトラム = 金 1 + 銀 1 → 2、インバー = 鉄 2 + ニッケル 1 → 3、コンスタンタン = 銅 1 + ニッケル 1 → 2、鋼鉄 = 鉄 1 + 石炭 2 → 1

### 11.1.2 基礎文明マシン（2026-10-02 実装、暫定）

工業 MOD が無くても基本の加工ができるよう、工業 MOD によくある基本のマシンを持つ。メイン要素ではないので、パイプは作らず**電力ケーブルだけ**にする。電力は Forge Energy（FE）なので、他 MOD の発電機・ケーブル・機械ともそのままつながる。登録は `registry/ModMachines`、処理は `machine/`。

* **部品**（`ModItems`。連携素材を多く使う重めのレシピ）
  * 銅線・金線 = インゴット 3 個 → 4 本
  * 基本回路 = 銅線 4 + レッドストーン 2 + スズの板 2 + クォーツ

### 11.1.5 連携の確認（2026-10-02、Mekanism 10.4.16・AE2 15.4.11）

`-PwithTechMods`（Mekanism・AE2・GuideME・JEI を読み込む）で GameTest `CompatGameTests` が相手の MOD を相手に動く（読み込まれていなければ素通り）。

* **共通金属のタグ**: Mekanism のスズ・鉛・オスミウム・ウラン・鋼鉄・青銅のインゴットと鉱石が、このMODの物と同じ `forge:` タグに入り、互いに代わりに使える
* **このMODのマシンで相手の素材**: Mekanism のオスミウム鉱石 → 粉砕機で粉 2 個、Mekanism のスズのインゴット → 金属プレスで板（レシピがタグで受ける）
* **送電**: Mekanism のユニバーサルケーブルでこのMODの発電機 → 電気炉、このMODの電力ケーブルで蓄電器 → Mekanism のエネルギーキューブ・AE2 のエネルギーアクセプター
* **電力ケーブルの扱い**: 出し入れの両方ができる他 MOD のブロック（エネルギーキューブ等）は受け手として入れるだけにする（勝手に吸い出さない）。引き出すのは出すだけの面と、このMODの蓄電器から
* **同じ金属のレシピの重なり**: インゴット → 塊、粗鉱・粉の精錬などで、Mekanism のタグで受けるレシピが先に当たり Mekanism の物ができることがある。同じタグなのでどちらでも使える（仕様どおり）
* **鉱石の生成の重なり（自動で譲る）**: バイオームの変更の最後の段（`AFTER_EVERYTHING`、すべての MOD が地物を足し終えた後）に、他 MOD の地物が置くブロックが `forge:ores/<金属>` に入っているかを見て、入っていればそのバイオームではこちらの同じ金属の鉱石を外す（`world/OreOverlap`）。置くブロックはバニラの `OreConfiguration` のほか、独自の設定（Mekanism の大きさを変えられる鉱石など）もフィールドを読んで見つける。MOD の名前の一覧は持たないので、Thermal・Immersive Engineering・Create 等でも同じく働く。相手の MOD の設定で生成が切られていれば、こちらが生成する。譲った金属と相手の地物はログに出る（`[worldgen] tin ore is generated by mekanism:ore_tin_small; ...`）
  * Mekanism 10.4.16 と入れると、スズ・鉛・オスミウム・ウランは Mekanism に譲り、銀・ニッケル・亜鉛・アルミニウムはこちらが生成する（GameTest `oreGenerationYieldsToOtherMods`）
  * 自動で譲らないときは `[ores]` の `skipWhenOtherModGenerates = false`。金属ごとに切る設定も残す
* 手で確かめること: Mekanism の物流パイプ・AE2 のインポート／エクスポートバスや ME インターフェースから、マシンの材料スロットへ入れ・結果スロットから出せるか（このMODのアイテムの出し入れの決まり §11.1.2 どおりか）

## 13. 戦術級コード体系 (Tactical Protocol System)

ルミナルステラの軌道衛星群・戦略兵站庫とリンクし、戦局を覆す大戦略兵器を投下する決戦システム。

### 13.1 二重承認プロトコル仕様

* **発動フロー**:
  1. プレイヤーが `tool_tac_pointer` を構え、「V」キーでコードを選択 ➔ 右クリック長押しで座標指定。
  2. サーバーへ `TacticalRequestPacket` 送信。
  3. 兵姫のAIが「同調率」「必要FE」を判定 ➔ 承認ボイスと共に天から兵器投下。
* **コンフィグ**: `enableTacticalGriefing: false` で地形破壊を無効化（mobへのダメージのみ付与）。

```java
// C2S: 戦術級コード要請パケット
public record TacticalRequestPacket(
    UUID valkyrieUUID,
    BlockPos targetPos,
    ResourceLocation protocolId
) implements CustomPacketPayload {
    public static final ResourceLocation ID = new ResourceLocation("tacticalvalkyries", "tactical_request");
    @Override
    public ResourceLocation id() { return ID; }

    public void handle(PlayPayloadContext context) {
        context.workHandler().execute(() -> {
            ServerPlayer player = (ServerPlayer) context.player().orElseThrow();
            TacticalProtocolManager.executeProtocol(player, valkyrieUUID, targetPos, protocolId);
        });
    }
}
```

* **描画**: `GungnirBeamRenderer` はバニラのビーコンシェーダーを拡張し、中心部を白、外縁部をネオンブルーに多重描画。照射時、周囲32mのプレイヤー画面にカメラシェイクエフェクト（パケット通知）を付与。
